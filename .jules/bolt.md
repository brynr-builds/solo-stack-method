## 2025-01-20 - O(N) Content Parsing Bottleneck
**Learning:** The content engine (`lib/content.ts`) was using `readType().find()` to retrieve single articles. Because `readType()` reads and parses the entire directory using `marked.parse` for every request, this created an O(N) disk I/O and CPU bottleneck, especially as the number of articles grows. `getArticle` was taking ~60ms to find a single article.
**Action:** When retrieving individual markdown files based on a slug, always construct the file path directly using the slug (with `path.basename` for security against traversal) and parse only that single file. Extracted the parsing logic to a helper `parseArticleFile` to keep data structures consistent. This reduced retrieval time from ~60ms to ~28ms (a >50% improvement).
